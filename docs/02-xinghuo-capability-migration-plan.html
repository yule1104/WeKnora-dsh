01 · 产品

一个入口

普通用户只使用 PG-AI-Foundation 工作台和 Chat，不迁移第二套聊天 UI。

02 · 业务

领域规则留在星火

需求、本体、ChangeSet、发布与部署由现有 FastAPI/MySQL 继续负责。

03 · 工程

一期保持 Go 主链路

BFF 位于星火后端，DSH 走 Gateway MCP，不在 WeKnora Go 中增加业务代理。

三层职责

页面、对话与知识在 PG-AI-Foundation；业务规则和事实数据在星火；复杂执行在 DSH。

候选与发布门禁

Agent 只能生成和校验候选，不能越过人工确认。

允许 Agent

查询需求/本体、创建 candidate、validate、列出 pending candidates。

禁止 Agent

confirm requirement、confirm changeset、publish release、delete project、生产部署确认。

并发保护

request_id、expected_hash、来源引用、审计操作者；基础版本变化返回 409。

总计划中的实施顺序

本子设计从 P1 开始，并依赖子设计 A 的 P2 Gateway。

P1绑定与只读工作台FastAPI BFF、/auth/me、Vue 四个 Tab
P3内部草稿 MCP查询、候选、校验、短期票据
P4需求 Agent澄清、证据、候选、人工确认
P5本体 Agentexpected hash、冲突、ChangeSet
P6资料同步external_id + hash + revision
P6编码 AgentGateway MCP、工作区、代码工具
P6部署迁移状态、日志、受控操作与审计
DONE旧入口只读新入口闭环后停止旧页面写入
避免双轨：星火原有 DshExecutor 只在迁移期兼容，不继续扩展；新增 DSH 流量统一进入 Runtime Gateway。
